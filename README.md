# ЧистоМаркет — сайт клининг-маркетплейса (лид-модель)

Сайт по мотивам [clean.orion-digital.biz](https://clean.orion-digital.biz): клиент проходит квиз,
видит цену и без оплаты отправляет заявку. Заявка сразу становится видна исполнителям, подключённым
по подписке в этом районе — они принимают её и дальше работают с клиентом напрямую.

## Структура репозитория

```
backend/   NestJS + PostgreSQL (Prisma) — API, авторизация, заявки, подписка исполнителей, отзывы
web/       Vite + React + TypeScript — сайт: квиз клиента, кабинет клиента, кабинет исполнителя
mobile/    Expo (React Native) — черновой каркас мобильного приложения, приостановлен (см. ниже)
```

**Приоритет — `web/`**: именно с сайта решили начинать.

## Бесплатный тестовый деплой (Render)

В репозитории есть `render.yaml` — Render по нему сам поднимет три сервиса: базу Postgres, backend
и статику сайта. Я не могу создать аккаунт на Render за вас (это привязка к вашей почте/GitHub), но
дальше буквально несколько кликов:

1. Зайдите на [render.com](https://render.com) и войдите через GitHub (бесплатно, карта не нужна).
2. **New → Blueprint** → выберите этот репозиторий (`Yunteris`), ветку `claude/assistant-agent-info-verify-02ay6x`
   (или `main`, если её туда смёржите) → Render найдёт `render.yaml` и покажет три сервиса разом.
3. Нажмите **Apply** — Render создаст базу, соберёт и запустит backend, соберёт и опубликует сайт.
   Первая сборка занимает несколько минут.
4. Когда backend поднимется, откройте его страницу в Render и скопируйте адрес вида
   `https://chistomarket-api.onrender.com`.
   - Если это имя оказалось занято, Render выдаст другое — в этом случае зайдите в сервис
     `chistomarket-web` → **Environment**, поправьте `VITE_API_BASE_URL` на реальный адрес backend
     и нажмите **Manual Deploy → Deploy latest commit**.
5. Готово — сайт открывается по адресу сервиса `chistomarket-web` (`https://chistomarket-web.onrender.com`),
   можно проходить квиз, регистрироваться, принимать заявки исполнителем.

Особенности бесплатного плана Render (нормально для теста, не для боевой эксплуатации):
- backend «засыпает» после ~15 минут без запросов — первый запрос после паузы отвечает с задержкой
  10–30 секунд, пока сервис просыпается;
- бесплатная база Postgres на Render работает 30 дней, затем её нужно пересоздать (или перейти на
  платный план/перенести на Neon/Supabase);
- миграции и сид базы (`prisma migrate deploy` + `prisma:seed`) уже вшиты в команду запуска backend
  в `render.yaml` — при каждом старте применяются автоматически, ничего руками накатывать не нужно.

Когда решите, как называть проект вместо «ЧистоМаркет», и захотите поменять дизайн — это отдельный
шаг (замена текстов/цветов/логотипа в `web/src`), сообщите здесь и я это сделаю.

## Как это устроено (модель заявки)

1. Клиент выбирает услугу/допуслуги/район/адрес/время → видит цену → жмёт «Оставить заявку».
   Если он не авторизован, форма регистрации/входа показывается прямо на странице, без перезагрузки.
2. Заявка создаётся сразу в статусе `SEARCHING` — **без оплаты**: платформа не берёт деньги за заказ,
   оплату клиент и исполнитель согласуют напрямую.
3. Заявка автоматически видна всем исполнителям с активной подпиской, у кого этот район указан в
   «Районах обслуживания». Кто первый нажал «Принять» — тот и получил заявку (гонка обрабатывается
   атомарным запросом на уровне БД).
4. Исполнитель ведёт заказ по статусам: выехал → уборка идёт → завершено.
5. Клиент может оставить отзыв после завершения — влияет на рейтинг исполнителя.

## Модель монетизации: подписка исполнителей

Клиенты ничего не платят платформе. Платят **исполнители** — абонентская плата за доступ к заявкам
(`backend/src/subscriptions`). Без активной подписки исполнитель не видит ленту заявок и не может их
принимать (`SubscriptionsService.assertActive`, вызывается из `OrdersService.feed`/`accept`).

Оплата подписки реализована как **архитектура под реальный автоплатёж**, но с платёжным провайдером-
заглушкой (`backend/src/billing/provider-charge.service.ts`):
- есть модели `SubscriptionPlan`, `Subscription`, `SubscriptionPayment`;
- есть ежедневная cron-задача (`SubscriptionsService.runDailyBilling`, `@nestjs/schedule`), которая
  продлевает подписки и списывает оплату при наступлении даты продления;
- сам вызов списания сейчас — заглушка, которая всегда отвечает «успех».

**Чтобы включить реальное автосписание**, нужно подключить ЮKassa (или другой провайдер с рекуррентными
платежами): первый платёж — с `save_payment_method: true`, сохранить `payment_method_id`, а на
продлениях — списывать по этому идентификатору без участия клиента. Это шаг с реальным договором и
ключами (`YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY` в `.env`), его нельзя сделать «изнутри кода» без вашего
подключённого мерчант-аккаунта — весь остальной код уже готов под замену заглушки на реальный вызов.

## Backend: локальный запуск

```bash
cd backend
cp .env.example .env
docker compose up -d          # поднимет Postgres
npm install
npx prisma migrate deploy     # применит уже готовую миграцию из prisma/migrations
npm run prisma:seed           # каталог услуг + тариф подписки (2990 ₽ / 30 дней)
npm run start:dev
```

API поднимется на `http://localhost:3000`.

## Web: локальный запуск

```bash
cd web
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Если backend запущен на другом адресе, задайте
`VITE_API_BASE_URL` в `web/.env`.

Проверено в этой среде: `npm run build` (TypeScript + Vite) проходит чисто, страницы визуально
рендерятся корректно (лендинг клиента и лендинг исполнителя проверены скриншотами). Живой сквозной
прогон с базой данных здесь сделать не удалось — в этой песочнице недоступен Docker/Postgres, так что
первый настоящий прогон «квиз → заявка → лента исполнителя → принятие» будет у вас локально.

## Что нужно докупить/подключить для реального продакшена

- **Хостинг** для `backend` (Postgres + Node) и `web` (статика) — например, Railway/Render/VPS + Vercel/Netlify.
- **ЮKassa с рекуррентными платежами** — для реального автосписания абонентки (см. раздел выше).
- **SMS-провайдер** (SMS.ru/SMSC.ru) — сейчас регистрация по телефону+паролю без кода подтверждения;
  для реального сайта обычно нужен вход по SMS-коду.
- **Домен** — например, перевести текущий `clean.orion-digital.biz` на новый сайт либо завести отдельный.

## Статус mobile/

Мобильный каркас (Expo) был собран **до** решения перейти на модель «сайт + бесплатная заявка +
подписка исполнителей» и всё ещё использует старую схему (клиент платит за заказ через эскроу).
Экраны и API-клиент там не синхронизированы с текущей моделью backend — прежде чем возвращаться к
мобильному приложению, экраны `mobile/src/screens/**` нужно переписать под тот же поток, что уже
реализован в `web/` (бесплатная заявка, подписка вместо оплаты заказа).
