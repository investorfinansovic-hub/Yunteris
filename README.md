# ЧистоМаркет — приложение клининг-маркетплейса

MVP-каркас мобильного приложения по мотивам [clean.orion-digital.biz](https://clean.orion-digital.biz):
клиент оформляет и оплачивает заказ уборки, система автоматически показывает его
проверенным исполнителям поблизости, исполнитель сам принимает заказ и ведёт его до завершения.

## Структура репозитория

```
backend/   NestJS + PostgreSQL (Prisma) — API, авторизация, заказы, оплата, отзывы
mobile/    Expo (React Native + TypeScript) — приложение под iPhone и Android
```

## Как это устроено (MVP-модель заказа)

1. Клиент выбирает услугу и допуслуги в калькуляторе → видит цену → оформляет заказ (`PENDING_PAYMENT`).
2. Клиент оплачивает → заказ уходит в поиск (`SEARCHING`) и появляется в ленте у исполнителей,
   обслуживающих этот район.
3. Первый исполнитель, нажавший «Принять», получает заказ (`ASSIGNED`) — гонка обрабатывается
   атомарным запросом на уровне БД, чтобы два исполнителя не могли принять один заказ одновременно.
4. Исполнитель ведёт заказ по статусам: выехал (`EN_ROUTE`) → уборка идёт (`IN_PROGRESS`) →
   завершено (`COMPLETED`) — на этом шаге оплата высвобождается исполнителю.
5. Клиент может оставить отзыв или открыть спор (`DISPUTED`) по гарантии сервиса.

## Backend: локальный запуск

```bash
cd backend
cp .env.example .env
docker compose up -d          # поднимет Postgres
npm install
npx prisma migrate dev --name init
npm run prisma:seed           # загрузит каталог услуг с ценами как на сайте
npm run start:dev
```

API поднимется на `http://localhost:3000`.

## Mobile: локальный запуск

```bash
cd mobile
npm install
npm run start
```

Откройте появившийся QR-код приложением **Expo Go** на iPhone (из App Store) — это позволяет
тестировать приложение на настоящем айфоне без Mac и без Apple Developer аккаунта.

Перед запуском отредактируйте `mobile/src/api/client.ts` — `API_BASE_URL` должен указывать на адрес,
доступный с телефона (не `localhost`, а IP компьютера в локальной сети, либо задеплоенный backend).

## Что нужно докупить/подключить для реального продакшена

Это то, что невозможно сделать «изнутри кода» — организационные и денежные шаги:

- **Apple Developer аккаунт** ($99/год) — обязателен для публикации в App Store. Для тестирования на
  своём iPhone через Expo Go он не нужен.
- **Хостинг backend + Postgres** — сейчас backend рассчитан на локальный запуск; для реального
  использования его нужно задеплоить (например, на Railway/Render/VPS).
- **ЮKassa** (или другой эквайринг) — сейчас `PaymentsService` — заглушка-симулятор
  (см. `backend/src/payments/payments.service.ts`). Нужны `YOOKASSA_SHOP_ID` и
  `YOOKASSA_SECRET_KEY`, доработка на реальные двухстадийные платежи (holdа/списание/возврат) и
  проверку вебхуков.
- **SMS-провайдер** (например SMS.ru/SMSC.ru) — сейчас регистрация идёт по телефону+паролю без
  подтверждения кодом. Для реального приложения обычно нужен вход по SMS-коду.
- **Сборка iOS без Mac** — через `eas build --platform ios` (Expo Application Services), сборка
  проходит в облаке; всё равно понадобится Apple Developer аккаунт для публикации.
- **Модерация App Store / Google Play** — обычно 1–3 дня; у маркетплейсов есть свои требования
  (например, к оплате внутри приложения).

## Дальнейшие шаги по продукту

- Верификация исполнителей (документы/фото, статус `verified` в `CleanerProfile` уже заложен).
- Push-уведомления клинерам о новых заказах в их районе (Expo Notifications).
- Геолокация вместо статичного списка районов — подбор ближайших исполнителей.
- Админ-панель для разрешения споров и управления каталогом услуг.
